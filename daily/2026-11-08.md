### 根因

- **commandai**：配置里的 API key 已过期（`~/.config/llm-api-check/config.json` 的 `user_W…`，2026-10-25 创建）。服务端 401 原文明确 `Your API key has expired. Log in again … run cmd login`。本机 `~/.commandcode/auth.json` 里有 2026-11-01 `cmd login` 写入的有效 key，用它打 `/alpha/*` 全部 200。
- **codebuddy**：2026-11-05 的「服务端无额度接口」结论错误。穷举漏了带 `/v2` 前缀的计量路径：`POST https://www.codebuddy.ai/v2/billing/meter/get-user-resource` 用现有 `ck_…` key 直接返回积分包剩余额度。

### 修复

- Commandai：`CommandaiRepo.CLIAuthKey()` 读 `~/.commandcode/auth.json`；`refreshCommandai` 在配置 key 认证失败（或配置无 key）时自动回退 CLI 凭据，`QuotaKeySource="cli"`，渲染层明示来源。
- CodeBuddy：新增 `CodebuddyRepo.Quota()` + `ParseCodebuddyQuota()`；详情/总览直接显示剩余/总量/已用百分比与到期时间，本地台账保留为按模型用量明细。
- 测试隔离新增宿主机状态：app 测试必须把 `CLIAuthPath` 指向临时不存在文件，否则开发机 CLI 已登录会让「认证失败」用例静默通过。
