## provider=codebuddy：服务端无额度接口 → 本地台账计算

**任务**：按 `~/prompt_boilerplates/Coding/index.md` 协议进入项目，新增 provider=codebuddy 的额度计算。

### 关键发现（穷举实测，非猜测）

服务端**没有**任何额度查询接口。逐一实测失败：

| 路径 | 结果 |
|:---|:---|
| `POST /billing/meter/get-user-resource-summary` 等 5 个 | 401 APISIX（需网页登录 Cookie，API key 不认） |
| `GET /v2/userinfo` | 400 `10001 only temporary api keys are supported` |
| `/v2` `/v3` × {usage,quota,credit(s),billing,plan,subscription,member,entitlement,balance,wallet,limits,resource} × {GET,POST} | 全 404（60+ 组合） |
| `/console/*` | 302 → 登录页 |

npm 包 `@tencent-ai/codebuddy-code@2.179.3` 的 `dist/codebuddy.js`（32MB）里 `fetchQuota`/`creditBalance`/`usageSummary`/`monthlyCredits` 全部零命中——上游 CLI 自己也不查余额，只显示「本轮消耗积分」（来自 SSE `usage.credit`）与 `/cost`（会话级）。

→ **额度只能从本地台账算**。

### 台账即真值源

`~/.codebuddy/projects/<slug>/<sessionId>.jsonl`，每行 `providerData.rawUsage.credit` = 该次调用**实际扣除的积分**（服务端下发的值，非本地估算）。

实测 663 条 → 52.85 积分。最小二乘拟合 `credit = a·非缓存输入 + b·缓存输入 + c·输出`：
- `deepseek-v4.1-flash`：R²=0.9981，留出集误差 −1.0%
- `default-model`：R²=1.0000，留出集误差 −0.3%

→ 确认 `credit` 与 token 用量线性一致，是真实扣费值。

### 协议细节（四源交叉验证）

- 认证头 **`X-API-Key`**（`dist/codebuddy.js` 的 `API_KEY_HEADER`），不是 Bearer
- `/v3/config` 另需 **`X-User-Id`**（任意非空值；缺失 → `data.models=null`）
- 401 两形状：无 key → APISIX HTML；坏 key → `{"message":"not_found"}`
- `credits` 三形状：`""`（未标注，**不是免费**）/ `"x0.34 credits"` / `"x0.00"`

### 踩坑

1. **台账行分类必须三态**：初版把「无 credit 字段的合法行」（reasoning/工具结果/快照，实测 1601 行）也算 `SkippedLines`，结果 2264 行里报 1601 行「损坏」——误导成台账大面积损坏。拆成 `billed`/`unbilled`/`corrupt` 后 SkippedLines=0。
2. **无时间戳的行漏出「全部」窗**：初版 `if e.Timestamp > 0 { for windows { if days==0 || ... } }`，把 timestamp=0 的行整个跳过时间窗循环，导致「全部」窗比 Total 少。测试 `TestParseCodebuddyLedgerMissingTimestamp` 抓到。
3. **测试环境已有 `COMMAND_CODE_API_KEY`** 会让既有 `TestCommandaiAddAndDetail` 失败（该用例期望缺 key → exit 2）。跑测试须 `env -u COMMAND_CODE_API_KEY`。
4. **`credits` 空串不能渲染成 `x0.00`**——会被读成免费。用 `HasMultiplier` 区分「未标注」与「显式 0」。
